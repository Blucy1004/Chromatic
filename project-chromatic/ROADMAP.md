# 남은 과제와 후속 예산

현재 확인한 개선은 계산 비용, 오류 복구, 진단 전술 문제와 재현성에 대한 것입니다. 경쟁력 있는 Elo와 학습에 따른 통계적 경기력 향상은 아직 입증하지 못했습니다.

## 다음 우선순위

1. 현재 진단 세트와 분리된 전술/엔드게임 홀드아웃, 더 많은 오프닝 쌍과 충분한 대결 표본을 준비합니다. 작은 세트에서 깊은 증명 옵션이 8/8이라고 일반적인 전술 실력으로 확대하지 않습니다.
   두 MLP 구성의 bootstrap validation loss가 초기보다 악화됐습니다. 검증 loss 기준 early stopping/후보 선택은 아직 구현하지 않았으며, 데이터 일반화와 함께 먼저 개선해야 합니다.
2. 완료된 자가대국의 결과 다양성과 WDL calibration을 추적합니다. 반복 무승부에 인공 패배를 주는 대신 탐색 예산·오프닝·초기 모델을 통제한 실험을 합니다. 장기 학습은 명시적인 시간/대국 예산을 받아 실행합니다.
3. 공간 CNN/ResNet을 별도 버전으로 구현하고 Tiny 4×64 / Small 6×96의 실제 CNN 비용을 비교합니다. 이번 두 구성은 residual MLP width 비교이며 CNN channels 비교가 아닙니다.
4. GPU/배치 추론·여러 자가대국 작업자를 측정합니다. 이번 검증은 CPU용 PyTorch입니다. 배치화와 공유 트리의 가상 손실은 아직 구현하지 않았습니다.
5. root reuse, make/unmake, 더 조밀한 move 표현과 비트보드를 각각 측정합니다. 반복·halfmove·모델 버전·원시 EP/특징이 다른 상태를 안전하게 구별하는 회귀 검사가 먼저 필요합니다.
6. 표준 Elo 가설의 pentanomial/SPRT 및 더 정교한 불확실성 추정을 도입합니다. 현재 SPRT는 pair-sign 가설에 한정됩니다.

## 조사했으나 채택하지 않은 경로

* ONNX Runtime: [공식 스레딩 문서](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)를 검토했습니다. 별도 런타임·스레드 풀과 배포 비용이 추가되며, 현재 직접 FP32 선택 헤드에서 큰 비용 절감이 먼저 확인됐습니다. ONNX 성능을 측정하지 않았으므로 어느 쪽이 우수하다고 주장하지 않습니다.
* FP16/INT8: 적용하지 않았습니다. 양자화 parity와 동일 시간 대결 검증도 실행하지 않았습니다.
* 공유 트리 병렬 MCTS: 구현하지 않았습니다. 현재 UCI 비동기 작업자와 추론 workspace 분리는 검증했지만 virtual loss/expansion synchronization은 후속 작업입니다. MSVC에서 TSan 검사를 수행했다고 주장하지 않습니다.
* Progressive widening/dynamic cpuct: 기본 알고리즘에 도입하지 않았습니다. FPU reduction은 옵션/진단 실험만 제공하며 기본값은 0입니다.
* 전역 중복 제거/디스크 기반 대형 replay: 현재는 bounded window 중복 감지와 bounded sparse replay입니다. 수백만 기록을 다루는 전역 인덱스는 후속 범위입니다.
* Immediate mate threat의 완전한 방어 증명: 기본은 자신의 즉시 메이트 증명입니다. 깊은 옵션도 공격자의 한정된 메이트만 증명하며, 모든 방어·전술 캡처를 해결하는 모듈은 아닙니다.

## 릴리스 판단

큰 모델이나 낮은 loss만으로 챔피언을 교체하지 않습니다. 현재 기준 모델을 배포 기본값으로 보존하고, 후보·원시 대국·정책 기록·대결 PGN을 유지합니다. 더 큰 실력 실험은 명시적으로 정한 계산 예산으로 이어가야 합니다.
