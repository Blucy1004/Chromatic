# 성능 보고서

2026-10-24, Windows 11 x64, Intel Core Ultra 7 255H(16 logical CPUs), 약 32GB RAM, MSVC 19.51 Release C++20, Python 3.12.14/PyTorch 2.14.1+cpu 환경에서 측정했습니다. 기본 모델은 원본 64×2 가중치입니다.

## 가설과 통제

기준 프로파일에서 탐색 시간 대부분이 신경망에 소비됐습니다. 주요 가설은 (1) 동일 FP32 행 연산으로 합법 정책 출력만 계산하면 불필요한 비용을 줄인다, (2) SSE2 FP32 내적이 정확성 허용치 안에서 더 빠르다, (3) 연속 트리/반복 이력 복사 축소가 메모리와 검색 부대 비용을 줄인다는 것이었습니다.

CPU affinity mask=1로 두 네이티브 벤치마크를 같은 코어에 고정했습니다. Full inference 1,000회와 같은 4개 위치에서 각각 128 MCTS 시뮬레이션을 수행했고 5회 원시 측정의 중앙값을 보고합니다. 모델 로딩/프로세스 시작/JSON 출력 시간은 네이티브 구간 시간에서 제외합니다. Root proof는 순수 커널 측정에서 비활성입니다. 시간 계측이 활성인 빌드이며 CPU 주파수는 고정하지 않아 일부 변동이 남습니다.

## 정책 헤드와 SIMD 분리 측정

| 경로 | 탐색 시뮬레이션/초 | 검색용 NN 평균 µs | 검색용 NN 평가/초 | NN 외 검색 시간 비율 |
|---|---:|---:|---:|---:|
| v0.1 기준, 전체 Scalar | 8,309 | 118.82 | 8,416 | 4.5% |
| 새 구조, 전체 Scalar | 7,769 | 121.74 | 8,214 | 3.9% |
| 합법 행 Scalar | 18,948 | 40.84 | 24,488 | 9.0% |
| 합법 행 SIMD | 66,164 | 10.83 | 92,304 | 27.3% |

전체 기준 대비 합법 Scalar는 2.28배, 기본 SIMD 경로는 7.96배였습니다. 같은 새 코드의 전체 Scalar와 비교한 합법 행 선택은 2.44배, 합법 Scalar 대비 SIMD는 3.49배였습니다. **트리 구조만으로 속도가 개선됐다고 주장하지 않습니다.** 실제 전체 Scalar 결과는 기준보다 느렸고, 유한성 검사와 부대 비용·측정 변동도 포함합니다. 주된 성능 근거는 선택 정책 헤드와 SIMD입니다.

전체 출력이 필요한 `zero eval`의 SIMD 평균은 53.45µs입니다. 검색에 쓰는 선택 헤드의 10.83µs와 혼동하지 않아야 합니다. 전체/선택 행은 같은 계산이며 20개 스칼라 검색의 방문 분포/가치는 기준선과 정확히 같았습니다. SIMD는 3개 구성에서 각각 100개 위치를 PyTorch와 대조했습니다.

## 메모리 압력 비교

4개 위치×4,096 시뮬레이션, 3회 중앙값의 프로세스 peak working set:

* 기준: 16,703,488 bytes.
* 새 연속 트리+선택 Scalar: 15,360,000 bytes.
* 이 측정에서 감소율: 8.0%.

이 값은 모델·런타임을 포함한 네이티브 프로세스 working set이며 트리 메모리만의 크기가 아닙니다. 두 경로의 neural call 중앙값은 14,019/14,019로 같았습니다. 별도 회귀 검사에서 64KiB tree vector capacity 상한도 확인했습니다.

## 두 실용 구성

동일한 기존 교사 위치 128개, 동일 seed, 200스텝, batch=32, 19개 위치의 독립 검증 분리로 학습했습니다. 아래는 **residual MLP width 비교**이며 CNN channels의 실험이 아닙니다.

| 구성 | width | residual 층 | SIMD 검색 NN µs | SIMD 시뮬레이션/초 | validation policy loss | validation WDL loss |
|---|---:|---:|---:|---:|---:|---:|
| tiny residual MLP | 64 | 4 | 12.18 | 55,940 | 8.908 | 1.892 |
| small residual MLP | 96 | 6 | 21.62 | 39,430 | 7.115 | 1.776 |

Small의 validation loss가 더 낮았지만 검색 비용은 더 컸습니다. 이 수치로 더 강하다고 판단하지 않았습니다. 색 교환 고정 시간 모델 대결도 실시했고 결과/한계는 STRENGTH_REPORT.md에 있습니다.

초기 모델 대비 validation 변화는 **tiny: policy 3.510→8.908, WDL 1.060→1.892; small: policy 3.467→7.115, WDL 1.041→1.776**였습니다. 두 구성 모두 학습 뒤 검증 loss가 악화되어, 128개 위치를 외우는 것과 일반화가 다르다는 문제를 확인했습니다. 더 큰 모델이나 더 낮은 훈련 loss를 배포 근거로 사용하지 않았습니다. 검증 기준의 early stopping/모델 선택과 데이터 다양성 검사가 후속 우선순위입니다.

## 데이터 생성과 학습

기준 재현은 완료된 190개 위치를 10.729초에 생성해 약 1,063 accepted positions/min이었습니다. 새 실행은 173개 위치, 0.540초, 약 19,232 new positions/min이었습니다. 오프닝, 결과, 종료 길이, 증명 경로와 기록 형식이 달라 **이 비율을 하나의 최적화의 인과 효과로 주장하지 않습니다.**

기준 bootstrap 학습은 load/save 포함 1,431 samples/s였습니다. 새 자가대국 학습의 compute-only는 6,348 samples/s, load/save/검증 포함은 801 samples/s였습니다. 데이터·검증·작업량 차이로 단순 상대 개선율을 계산하지 않습니다.

모든 원시 샘플과 조건은 `reports/final/*.json`, 모델 크기 비교는 `reports/model-scaling/comparison.json`, 원본 재현은 `reports/baseline-reconstruction.json`에 있습니다. 속도·메모리 개선은 Elo 개선과 별도로 판단합니다.
