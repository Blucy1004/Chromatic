# CHROMATIC 1.0 구조와 버전

## 검색과 추론

```text
UCI 입력 -> 합법 수/종료 판정 -> 제한된 메이트 증명 -> PUCT-MCTS
                                                     |
                           FP32 residual MLP <- 합법 정책 행/WDL
                                                     |
          방문 분포 + 선택 수 -> 실제 게임 결과 -> bounded replay
                                                     |
                     검증 분리/학습 -> 후보 -> 색 교환 UCI 대결
                                                     |
                         신뢰하한 통과 -> 챔피언 이력 / rollback
```

C++ 엔진은 외부 체스 엔진이나 Python 프로세스를 실행하지 않습니다. Python 도구는 데이터 생성·학습·대결·독립 규칙 대조를 담당합니다. 교사 데이터는 원래 128개 부트스트랩만 사용했고 이후 세대는 자가대국 데이터로 학습합니다.

트리는 노드와 간선을 각각 연속된 vector에 저장하고 정수 인덱스로 연결합니다. 재할당 뒤에 무효가 되는 포인터를 저장하지 않습니다. `TreeMemoryMB`는 두 vector의 capacity를 합친 실제 보존 메모리를 제한합니다. 노드 또는 바이트 상한에 닿으면 새 잎을 저장하지 않고 평가하여 계속 진행합니다. 경로 버퍼와 추론 작업공간은 검색 안에서 재사용합니다.

합법 수를 확인하는 임시 보드는 기물·권리·카운터만 복사합니다. 반복 이력이 필요한 실제 검색 경로에서는 전체 이력을 보존합니다. 반복 해시는 기물/차례/캐슬링과 합법 EP 권리를 포함하고, 50수 및 반복 이력이 다른 상태를 합치지 않도록 현재 transposition이나 루트 트리 재사용은 하지 않습니다. 트리는 검색마다 생성·소멸합니다.

PUCT는 `Q + cpuct*P*sqrt(parent_visits+1)/(1+N)`입니다. Q는 부모 차례 관점이며 잎에서 한 간선을 올라갈 때마다 부호를 반전합니다. WDL은 둘 차례 관점의 W,D,L이고 가치값은 W-L입니다. 미방문 Q의 기본값은 0이며 `FPUReduction`은 기본 0인 실험 옵션입니다. Root noise는 Dirichlet alpha=.3과 epsilon을 사용하고 대결에서는 noise와 온도를 사용하지 않습니다.

## 전술 증명과 노드 수

메이트 모듈은 종료 상태만 사용하는 제한된 AND/OR 증명입니다. 물질 평가, 알파베타, quiescence는 없습니다. 주어진 수·노드·시간 상한 안에서 공격자의 강제 메이트를 증명한 경우만 수를 확정합니다. 상한이 소진되면 `unknown`으로 일반 MCTS에 돌아갑니다. 현재 기본은 최대 256개 증명 노드와 1플라이이며, 깊은 진단 옵션은 최대 5플라이입니다.

메이트가 증명됐을 때 요청된 시뮬레이션을 수행했다고 기록하지 않습니다. 증명으로 뒷받침된 루트 업데이트 하나만 기록하고 JSON에 증명 노드 수를 따로 제공합니다. UCI `nodes`는 일반 MCTS와 증명으로 뒷받침된 루트 업데이트 수이며 증명 모듈의 전체 작업 수와 같지 않습니다. 비용 비교는 시간 제한으로 수행하고, 순수 MCTS 커널 성능 측정에서는 증명 모듈을 끕니다.

## 입력 v1과 정책 v1

`a1=0`, `h8=63`, 절대 좌표를 사용합니다. 흑 차례라고 회전하거나 색을 바꾸지 않습니다. 입력은 FP32 20×64=1,280입니다.

| 평면 | 의미 |
|---|---|
| 0..5 | 백 P,N,B,R,Q,K |
| 6..11 | 흑 P,N,B,R,Q,K |
| 12 | 백 차례=1, 흑 차례=0 전체 채움 |
| 13..16 | 백 O-O, 백 O-O-O, 흑 O-O, 흑 O-O-O |
| 17 | 원시 EP 칸 one-hot |
| 18 | min(halfmove,100)/100 |
| 19 | min(현재 위치 반복 횟수,3)/3 |

과거 기물 배열을 모두 입력하지는 않습니다. 전체 이동 이력은 규칙·데이터 복원에 보존하고 현재 반복 횟수를 입력합니다. 이미 성립한 3회 반복과 100 halfmoves에서 즉시 무승부를 청구합니다. 다음 수의 사전 청구는 지원하지 않습니다. 메이트가 50수 판정보다 우선합니다.

정책은 4,672개 logits입니다. 보통 수/Q 승격은 `from*64+to`. N/B/R 승격은 `4096+from*9+(to_file-from_file+1)*3+(promotion_piece-2)`이며 N=2,B=3,R=4입니다. 캐슬링도 왕의 시작/도착 칸으로 인코딩합니다. 합법 수 사이의 인덱스 충돌을 검사했습니다.

학습과 탐색 모두 합법 수만 정규화합니다. 추론의 선택 헤드는 같은 선형 층에서 필요한 행만 계산합니다. 비선택 위치의 JSON 값 0은 확률이 아닌 미사용 logit 슬롯입니다. `evallegal` 출력을 전체 action softmax에 직접 넣으면 안 됩니다. `zero eval`은 전체 logits를 반환하여 PyTorch 대조에 사용합니다.

## 모델 파일 v1

`ZERO0001`, little endian FP32, uint32(inputs,width,blocks,actions) 헤더를 유지합니다. Input -> residual 층들 -> Policy -> WDL 순으로 각 Linear의 row-major weight와 bias를 저장합니다. 구조는 `ReLU(Linear(input))`, 반복 `ReLU(x+Linear(x))`, Policy/WDL 두 헤드입니다.

검증한 구성은 기준 64×2, Tiny 64×4, Small 96×6입니다. 여기서 64/96은 MLP hidden width이며 공간 CNN의 channels라고 주장하지 않습니다. 이번에 새 CNN을 구현한 것은 아닙니다. SIMD는 SSE2 FP32 연산이며 양자화하지 않습니다. 스칼라 경로는 이전 행 연산 순서를 유지합니다. SIMD/PyTorch 비교는 절대오차 2e-5를 사용합니다.

## 데이터 v2, checkpoint v2, replay index v1

자가대국 기록 v2는 v1의 root FEN/이동 이력/현재 FEN/정책/WDL에 다음을 추가합니다: 압축한 FP32 입력, 합법 action 목록, 선택한 action/UCI, seed, 예산과 실제 방문 수, 모델/게임 ID, 실제 종료 이유. 입력은 little endian FP32를 zlib+base64로 압축하며 로더에서 독립적으로 다시 만든 입력과 비교합니다. v1 데이터도 지원합니다.

미완료 기록은 결과 필드를 만들지 않고 `pending/`에 원자적으로 저장합니다. 기본 32플라이마다 진행을 저장하고, 중단된 기록의 마지막 위치와 선택 수에서 재개합니다. 완료된 최상위 shard만 학습합니다. 원시 대국 데이터를 replay 용량 제한 때문에 삭제하지 않습니다.

Replay는 sparse target을 보관하고 minibatch 때만 dense mask/정책을 만듭니다. 최근/과거 reservoir를 나누고, 실제 샘플 수·중복 창 범위·선택한 원본 줄과 해시를 원자적으로 저장합니다. 같은 게임이나 같은 입력 위치가 검증과 학습에 동시에 들어가지 않도록 그룹을 합쳐 분리합니다.

Checkpoint v2는 모델·optimizer·step·스케줄·Python/NumPy/Torch/CUDA RNG·샘플러·설정·데이터 해시·샘플 수를 저장합니다. reader는 v1/v2 모두 지원합니다. 새 학습은 v2 설정을 검증하고, v1 exact continuation은 `--legacy`로 명시합니다. 저장 전에 모델과 optimizer의 유한성을 확인하고 `.tmp`/fsync/replace 및 `.prev` 복구를 사용합니다.

## 대결 통계와 동시성

색을 교환한 같은 오프닝 두 판을 묶고, 같은 오프닝의 반복은 다시 하나의 cluster로 묶습니다. 점수는 W=1,D=.5,L=0이며 신뢰구간은 오프닝 cluster 평균의 가중 양측 Hoeffding 구간입니다. 같은 오프닝 반복으로 독립 증거 수를 부풀리지 않습니다. 신뢰하한이 승격 기준을 넘을 때만 승격하고, 상한이 .5 아래일 때만 열세가 입증됐다고 표시합니다. 불완료/오류가 있으면 Elo와 승격을 보류합니다.

SPRT는 비긴 쌍을 제외한 pair sign Bernoulli 가설에 한정합니다. Elo 가설 SPRT는 구현하지 않았습니다. `--sprt` 사용 시 모든 중지 시점을 덮는 보수적 신뢰구간을 별도로 적용합니다.

현재 MCTS는 단일 작업자입니다. UCI 입력과 검색 작업자는 분리되어 isready/stop을 처리하고, 모델·위치를 바꾸기 전에 검색을 join합니다. stop은 atomic, 출력은 mutex, 추론 workspace는 검색 소유입니다. 공유 트리/가상 손실/배치 평가를 도입했다고 주장하지 않습니다.
