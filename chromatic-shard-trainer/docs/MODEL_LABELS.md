# CHROMATIC 모델 호환성과 라벨 해석

이 문서는 보존된 CHROMATIC Python/C++ 인터페이스와 새 샤드 학습기의 실제 구현을 기준으로 한다. 원본 CHROMATIC 1.0, 메모리 회수 개선 엔진, Muyeong의 코드는 수정하지 않는다. 새 학습기는 기존 모델과 인코딩을 별도 `vendor/zero` 사본에서 재사용하며, 후보 모델을 챔피언에 자동 덮어쓰지 않는다.

## 1. 실제 모델 인터페이스

현재 챔피언은 **입력 1,280개, 폭 64, 잔차 블록 2개의 MLP**다. CNN이 아니다. 입력을 20개 평면 × 64칸으로 만든 뒤 평탄화한다. 칸은 절대 좌표이며 흑 차례라고 보드를 뒤집지 않는다.

| 평면 | 내용 |
|---|---|
| 0–5 | 백의 폰·나이트·비숍·룩·퀸·킹 위치 |
| 6–11 | 흑의 같은 6종 기물 위치 |
| 12 | 백 차례이면 전체 1, 흑 차례이면 전체 0 |
| 13–16 | 백 킹사이드·백 퀸사이드·흑 킹사이드·흑 퀸사이드 캐슬링 권리 |
| 17 | 앙파상 대상 칸 |
| 18 | `min(halfmove_clock, 100) / 100` |
| 19 | 확인된 반복 횟수 1·2·3을 3으로 나눈 값 |

공유 부분은 `ReLU(input(x))` 뒤에 `ReLU(h + Linear(h))`를 두 번 적용한다. 출력 헤드는 서로 구분된다.

- **Policy:** 4,672개의 logits. 앞의 4,096개는 `from_square × 64 + to_square`다. 퀸 승격은 이 일반 이동 인덱스를 쓴다. 뒤의 576개는 나이트·비숍·룩 승격과 이동 파일 차이를 인코딩한다. 존재하는 출력 인덱스가 모두 합법 수라는 뜻은 아니며 학습·추론에서 합법 수 마스크를 적용한다.
- **WDL:** 3개 logits를 softmax한 **현재 차례 기준 승·무·패**다. `V = P(W) − P(L)`이며 범위는 −1부터 +1이다. 자식 위치의 차례가 바뀌므로 부모 관점으로 되돌릴 때 부호가 반전된다.

가중치 내보내기는 기존 `ZERO0001` 형식을 그대로 사용한다. 8바이트 magic 뒤에 입력 수·폭·블록 수·action 수의 little-endian 정수 4개, 이어서 각 Linear 층의 FP32 행 우선 weights와 bias를 기록한다. 학습용 optimizer·scheduler·RNG는 `.pt`에 있고, C++ 추론용 `.zero`에는 모델 가중치만 있다. 새 checkpoint bundle은 둘의 SHA-256뿐 아니라 헤더·길이·실제 tensor bytes가 일치하는지 검증한다.

## 2. 기존 학습기와 새 회전형 제어기의 관계

기존 `zero.training.train(..., resume=...)`는 checkpoint에 적힌 데이터 소스 목록과 학습 설정이 현재 요청과 **정확히 같아야** 재개한다. 이 제약은 동일 작업의 정확한 연속 실행을 위한 것이다. 샤드마다 파일이 달라지는 회전 학습에서 그대로 호출하면 거절되며, 이를 피하려고 샤드마다 `init`을 호출하면 optimizer와 진행 상태를 매번 새로 시작하게 된다.

새 제어기는 기존 `PolicyWDL`, 인코딩, 가중치 내보내기와 checkpoint 형식의 검증 코드를 재사용한다. 여기에 별도의 샤드 진행 상태를 두어 파일이 회전해도 같은 학습 작업의 optimizer를 이어 간다.

| 상황 | 동작 |
|---|---|
| 새 학습 작업 시작 | 보존된 챔피언에서 모델 구조와 weights를 가져오고 새 작업용 AdamW·scheduler를 초기화한다. 과거 128개 bootstrap 작업의 optimizer를 억지로 이어 붙이지 않는다. |
| 같은 작업의 `-Resume` | 모델·optimizer·scheduler·Python/NumPy/Torch RNG·샘플러 Generator·샤드·epoch·순열·순열 offset·replay를 복원한다. |
| 다음 샤드 진입 | 현재 optimizer와 전역 step을 유지한다. 이전 샤드의 대표 학습 표본을 제한된 replay에 남긴다. |
| 실패한 저장·학습 | 마지막 검증된 commit이 기준이다. 실패한 샤드는 성공으로 처리하거나 삭제하지 않는다. |

학습률은 현재 구현에서 `base_lr × max(0.05, 0.999 ** step)`이다. 장기 회전 학습에서 단순 지수 감쇠가 사실상 0에 도달하지 않도록 바닥을 둔다. scheduler 설정도 재개 설정 서명에 포함한다. 이 설정이 최적의 강도를 보장하는 것은 아니며 실험으로 조정해야 한다.

`progress.completed`와 `progress.active`는 checkpoint와 SQLite commit으로 함께 관리한다. 완료되지 않은 저장 시도는 성공한 샤드로 세지 않는다. primary checkpoint가 손상되면 같은 commit의 mirror를 확인하고, 둘 다 사용할 수 없으면 필요한 원본 샤드가 남아 있는 이전 정상 commit만 선택한다. 복구할 데이터가 없으면 임의로 건너뛰지 않고 중단한다.

## 3. 공식 평가 데이터의 관점과 FEN 한계

[공식 Evaluation Database](https://database.lichess.org/#evals)는 평가 깊이, `knodes`, PV와 CP 또는 mate를 제공한다. CP와 mate는 **백 관점**이다. 이 관점과 king-to-rook 캐슬링 표기는 [공식 CloudEval 스키마](https://raw.githubusercontent.com/lichess-org/api/master/doc/specs/schemas/CloudEval.yaml)에 명시되어 있고, [공식 exporter](https://raw.githubusercontent.com/lichess-org/database/master/src/main/scala/Evals.scala)는 캐시 평가를 JSONL로 내보낸다.

흑 차례에서 백 기준 CP가 +200이면 흑 기준 평가는 −200이다. CP를 승률로 읽거나 CP/100을 확률로 쓰지 않는다. 최종 WDL 목표 역시 모델과 같은 현재 차례 관점으로 바꾼다.

덤프의 FEN은 기물·차례·캐슬링·앙파상이라는 **4개 필드**뿐이다. 따라서 다음 정보는 복원할 수 없다.

- 실제 몇 번째 수, 첫 6–12플라이인지 여부
- 50수 규칙용 실제 halfmove clock
- 이전 위치 이력과 반복 횟수

평가 레코드는 인코더 호환을 위해 누락된 카운터를 `0 1`로 채우지만, 이를 실제 관측값으로 주장하지 않는다. `history_known=false`, 누락 필드와 `phase_basis`를 남긴다. 기본 반복 평면 값도 “실제 반복이 없었다”는 증거가 아니라, 주어진 루트만으로 복원한 값이다. 기물 수와 남은 전력으로 정한 opening/middlegame/endgame은 **material proxy**다. 후반에 기물이 많이 남아 있으면 이 proxy가 opening으로 분류할 수도 있다.

이에 반해 공식 CC0 오프닝 카탈로그에서 만든 anchor는 시작 위치부터 실제 이동 이력을 가진다. 시작 위치와 0–12플라이 층을 나눠 표본을 고르며 시작 위치는 학습·replay에서 보존한다. 이 정책은 카탈로그의 관측된 다음 수 집계에 따른 약한 모방 목표다. 카탈로그 등장 횟수를 실제 대국 빈도나 MCTS 방문 분포라고 부르지 않는다.

**오프닝 카탈로그에는 결과 기반 WDL 정답이 없다.** 따라서 해당 anchor의 `value_weight`는 0이다. 내부 WDL placeholder `[0, 1, 0]`도 관측된 무승부가 아니며 학습과 WDL 검증 손실에서 제외된다. 시작 위치가 정책 데이터에 포함됐다는 것만으로 그 위치의 Value가 교사 정답으로 학습됐다고 해석하면 안 된다.

## 4. 품질 검사와 부분 Policy 목표

현재 기본 품질 기준은 깊이 12 이상, `knodes` 10 이상이다. `knodes` 10은 10노드가 아니라 **10,000노드**다. 설정을 바꾸면 실행 설정과 로그에 남는다.

검사에는 FEN 구조·기물 배치의 합법성, 종료 위치 제외, 유한한 score, PV 존재, PV 첫 수와 기본적으로 전체 PV의 합법성이 포함된다. king-to-rook 형식은 `Board.parse_uci()`를 통해 표준 캐슬링 이동으로 정규화한 뒤 기존 action 인덱스로 바꾼다. 동일 첫 수가 중복된 PV는 해당 평가에서 거절한다.

여러 평가가 있으면 사용 가능한 평가 중 깊이, 노드 수, PV 수 순으로 선택한다. 더 깊은 평가의 PV가 불법이면 유효한 다른 평가를 선택할 수 있으며 거절 이유를 기록한다. 여러 PV의 side-to-move score에 온도를 적용한 softmax를 목표 분포로 삼지만, 이는 **제공된 PV 사이의 분포**다. 관측되지 않은 합법 수를 모두 평가했다는 뜻이 아니다.

단일 PV도 one-hot 형태의 부분 모방 목표로 사용할 수 있다. 완전한 최적 정책 분포로 오인하지 않도록 `policy_kind`, 관측한 수 개수, 합법 수 개수, `policy_support_complete`와 낮은 가중치를 기록한다. 데이터가 제공하지 않은 수가 객관적으로 나쁘다고 인증하지 않는다.

학습의 실제 목적함수는 각 행의 `policy_weight × policy_CE + value_weight × WDL_CE`를 전체 행 수로 나눈 값이다. 이 때문에 약한 라벨의 가중치가 실제 기여도를 낮춘다. 로깅용 Policy/WDL 평균 손실은 각 헤드에서 유효한 가중치 합으로 나누며, Value 가중치가 모두 0이면 WDL 손실을 `null`로 표시한다.

mate는 CP 보정식에 거대한 숫자로 넣지 않고 부호를 별도로 처리한다. mate 부호로 만든 목표도 약한 교사 신호이며, CHROMATIC이 해당 메이트를 직접 증명했다는 뜻은 아니다. 비종료 위치에서 mate 0은 JSON 정수의 부호를 복원할 수 없으므로 거절한다. 누락된 반복·50수 이력이 해결되는 것도 아니다.

## 5. 실제 독립 CP→WDL 보정 결과

평가 덤프 자체에는 실제 W/D/L 결과가 없다. 따라서 별도로 받은 공식 CC0 완료 게임 PGN의 기존 `%eval` 주석과 실제 Result 태그를 사용했다. CP 주석은 백 관점으로 읽고, 첫 12플라이를 제외하며 게임당 최대 8개 위치를 고른다. 서로 다른 행이어도 같은 게임의 행은 항상 같은 그룹에 속한다.

이번 자료는 **3,831행, 483게임**이다. 공식 오프닝 3,865개 행에서 시작~12플라이의 5,605개 placement family를 예약한 뒤, 그 family가 등장하는 보정 게임 전체를 제외하는 검사를 수행했다. 이번에는 겹치는 게임이 0개였다.

| 그룹 | 게임 | 위치 | 용도 |
|---|---:|---:|---|
| fit | 284 | 2,242 | 두 보정 매개변수 학습 |
| validation/dev | 107 | 854 | 매개변수 선택과 상수 사전분포 대비 검사 |
| test | 92 | 735 | 선택에 쓰지 않은 최종 보정 지표 |

보정식은 양의 scale과 음수가 아닌 draw margin을 갖는 대칭 ordinal logistic이다. 선택된 scale은 **491.47197 CP**, draw margin은 **26.20299 CP**다. 이 두 수는 이번 게임 표본에서 맞춘 값이며 모든 Stockfish 버전·시간 제어·실력에 보편적으로 적용되는 상수가 아니다.

한 게임의 전체 가중치가 1이 되도록 계산한 test 지표는 다음과 같다.

| 지표 | 학습된 CP 보정 | fit 결과 비율만 쓰는 상수 사전분포 |
|---|---:|---:|
| NLL | 0.655274 | 0.790870 |
| 3분류 Brier | 0.408531 | 0.528837 |
| top-class ECE | 0.047169 | 0.062895 |

이 값은 **보정기**의 지표다. 새 신경망의 지표로 복사해서 쓰면 안 된다. 실제 숫자와 입력 출처·해시·그룹은 [보정 보고서](../reports/calibration-report.json), [보정 아티팩트](../fixtures/calibration.json)에 있다. 학습된 신경망은 별도로 test 게임의 실제 결과와 비교하여 NLL/Brier/ECE를 계산한다. soft WDL 라벨과의 일치도도 실제 결과에 대한 보정 오차와 구분한다.

보정기는 필요한 독립 holdout 게임 수, 세 결과 클래스의 fit 포함, validation NLL의 상수 사전분포 대비 조건을 통과해 `accepted`가 됐다. 표본이 작으므로 CP Value 라벨의 confidence는 **0.25**로 제한한다. 이 승인은 완벽한 플레이의 승률, 큰 실력 향상, 모델 승격을 뜻하지 않는다. 사람의 실력·시간 제어와 여러 Stockfish 버전이 섞인 **실제 대국 결과의 경험적 분포**를 추정했을 뿐이다.

보정이 승인되지 않거나 아티팩트를 사용할 수 없으면 CP 행의 Value 가중치를 0으로 둔다. 보정 데이터의 모든 기록 family는 새 NN 학습 샤드에서 제외한다. 이 제외는 새 샤드의 누수를 막는 조치이며, 기존 챔피언의 과거 학습을 되돌린다는 뜻은 아니다. 덤프에는 원래 게임 ID가 없어 모든 평가의 게임 단위 계보를 증명할 수는 없다. 고정 split은 이용 가능한 위치·placement family 기준으로 보수적으로 관리한다.

## 6. Value 일관성 진단과 승격 판단

평가 도구는 시작 위치와 합법 첫 수 20개를 직접 추론한다. 부모 Value를 `V(s)`라 할 때, 자식 WDL의 관점을 바꾼 값은 `P_child(L) − P_child(W)`다. 보고서에는 각 수의 Policy, 자식 WDL, 부모 관점 값, 부모·자식 차이를 기록한다. 추가로 `abs(V(s) − max_a[-V(child_a)])`와 모든 자식 백업이 음수인지 여부도 출력한다.

이 수치는 한 수 사이의 **자기 일관성 진단**이다. 실제 정답 정확도, 보장된 미니맥스 깊이 또는 Elo가 아니다. 시작 위치에서 부모가 크게 유리하고 모든 자식이 크게 불리하다는 현상을 찾는 데 유용하지만, 이 잔차만 낮추면 강한 모델이 된다는 결론은 성립하지 않는다.

현재 승격 평가기는 고정 validation/test 손실, 실제 독립 결과의 Brier/ECE, 원본 프레임 무결성, family 누수 감사, 평가 중 후보 head 안정성, 전술 오류·정확도, 색을 바꾼 고정 시간 대국을 함께 확인한다. 각 validation/test에 최소 1,000위치, 완료 대국 최소 64판, 점수의 95% 하한이 0.5를 넘는 조건도 요구한다. 소규모 검증의 몇 판만으로는 이 대국 근거를 채울 수 없다.

다만 시작 위치의 부모·자식 잔차는 현재 **보고 항목**이며, 폭넓은 위치 집합에서 검증된 독립적인 자동 승격 임계값은 아직 없다. 한 개의 시작 위치와 첫 20수만으로 일반화·가치 보정을 보장할 수 없다. 전술의 정확한 첫 응수 일치율도 다른 좋은 수가 있을 수 있는 지표다. 이 한계 때문에 학습 loss 감소, 보정기 승인, 더 자연스러운 첫 수를 각각 곧바로 모델 승격으로 연결하지 않는다.

모든 독립 gate를 통과하더라도 평가 결과는 수동 검토 대상이다. 프로그램은 챔피언을 자동으로 덮어쓰지 않으며 후보 checkpoint·네이티브 모델·평가 근거를 별도로 보존한다.
