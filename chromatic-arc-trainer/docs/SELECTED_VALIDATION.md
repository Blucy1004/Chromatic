# 선택한 분석만 PV를 검사하는 별도 실험

`shardtrain/quality_fast.py`는 기존 `quality.py`를 수정하지 않는 별도 구현이다. 이 실험 자체는 기본 데이터 검증 모드를 바꾸지 않는다. 공식 로컬 60,000행에서 선택 라벨 및 레코드 거부 결과의 바이트 동등성을 확인했다. 정규화 단계는 2.086배 빨라졌으며, 전체 학습 파이프라인의 가속과 최종 채택은 별도의 실측으로 판단한다.

기존 파서는 한 레코드의 모든 분석에 대해 FEN/PV·합법성을 검사하고 유효한 후보 중 `(depth, knodes, PV 수)`가 가장 큰 것을 선택한다. 같은 순위면 원본에서 먼저 나온 후보를 선택한다. 신경망에 전달되는 정책·WDL·가중치는 선택된 분석 하나로 만든다.

새 함수 `normalize_selected(raw, config=None, calibration=None, source=None)`는 다음 순서를 사용한다.

1. 기존 `_integer`와 같은 순서·기준으로 모든 분석의 깊이·노드·PV 개수 메타데이터를 확인한다.
2. `(depth, knodes, PV 수, -원본 인덱스)` 순으로 정렬한다.
3. 가장 높은 후보부터 **기존 파서**에 해당 분석 하나를 전달한다. 선택된 후보의 모든 제공 PV와 그 끝 수까지 기존 합법성 검사를 그대로 수행한다.
4. 후보가 실패하면 다음 후보를 검사한다. 모두 실패하면 원래 전체 파서를 재실행하여 기존 레코드 거부 사유와 우선순위를 보존한다.

메타데이터 순위의 PV 개수는 후보가 완전히 유효한 경우 실제 파싱된 PV 개수와 같다. 따라서 같은 메타데이터 기준으로 내림차순 검사해 처음 유효한 후보를 고르면 전체 검사 후 최대값을 고르는 기존 선택과 같다. 동점에 원본 인덱스를 포함해 순서도 보존한다. 일부 극단적인 JSON 정수 CP/mate가 기존 파서의 숫자 변환에서 `QualityError` 밖의 overflow를 일으키는 경우에는 전체 파서로 돌아가 기존 동작을 보존한다.

이 모드에서는 사용하지 않은 하위 분석의 합법성을 검사했다고 주장하지 않는다. `source_eval`에 `validation_mode`, 선택 인덱스, 메타데이터 거부, 완전 검사 시도 인덱스, 시도 중 거부, `skipped_lower_evaluation_indices`와 `skipped_lower_evaluations`를 기록한다. `rejected_evaluations`도 **알려진 거부만** 담는 부분 감사 결과이며 `rejected_evaluations_scope`가 이 범위를 설명한다. 실패 후보의 모든 PV가 끝까지 유효했다는 의미로 표기하지 않는다.

`semantic_record()`는 이 감사 범위의 차이만 제외한다. 보드와 이력, FEN·identity·family·similarity·phase, 정책과 WDL, 가중치·보정 해시, 선택된 점수·깊이·노드·PV 첫 수·검사 길이·평가 관점, provenance 등 나머지 필드는 모두 비교 대상이다. 앞으로 기존 파서에 새 학습 필드가 생겨도 자동으로 비교에서 빠지지 않는다.

짧은 회귀 테스트는 정상·동점·가장 깊은 분석 실패·중복 첫 수·잘못된 메타데이터·흑 관점·mate·캐슬링·언더프로모션·독립 보정·선택된 긴 PV·극단 숫자 및 거부 우선순위를 포함한다. 현재 32개가 통과했다.

독립 코퍼스 비교는 다음 도구로 실행한다. 다른 성능 실험과 동시에 실행하지 않는다.

```powershell
& 'C:\Users\fly_t\chromatic-xpu\Scripts\python.exe' .\tools\validate_quality_fast.py `
  --max-records 60000 --deadline-seconds 300
```

도구는 로컬 공식 fixture의 출처·SHA를 확인하고 bounded Zstandard 스트림을 읽는다. 같은 파싱된 레코드에 full과 selected를 번갈아 먼저 실행해 순서 편향을 줄인다. 입력 전체를 RAM에 모으지 않는다. 정규화 시간·처리량·FEN/PV 호출 수, 모든 성공·거부 결과의 canonical JSON 바이트 해시, 불일치 예시 최대 10개와 소스 무결성을 `reports/quality-selected/`에 기록한다. CP/WDL 정책 라벨의 숫자가 같아 보이는 수준이 아니라 모든 비교 필드의 직렬화 바이트와 레코드 거부 결과가 정확히 같은지 검사한다.

## 공식 60,000행 실제 검증 결과

Python 3.11.9 전용 환경에서 같은 로컬 공식 fixture와 독립 보정 파일을 사용했다. 60,000행을 모두 비교했고 양쪽에서 59,069행을 수용했다. 거부한 931행의 사유도 정확히 같았다. 의미 필드 불일치는 0개였다.

| 항목 | 기존 전체 분석 검사 | 선택 분석 검사 |
|---|---:|---:|
| 정규화 시간 | 73.6510초 | 35.3067초 |
| 입력 레코드/초 | 814.65 | 1,699.40 |
| PV 검사 호출 | 387,081 | 129,129 |
| FEN 검사 호출 | 60,000 | 60,477 |
| 수용 / 거부 | 59,069 / 931 | 59,069 / 931 |

FEN 검사는 실패 후보의 fallback 때문에 조금 늘었다. 전체 PV 검사 호출은 약 66.6% 줄었다. 선택 모드는 수용 레코드에서 하위 분석 54,900개를 미검사로 명시했다. 거부 사유는 중복 PV 첫 수 127, 불법 위치 275, 잘못된 knodes 184, 낮은 깊이 113, 낮은 노드 232개로 양쪽이 같았다.

성공 라벨과 거부 결과 전체의 canonical JSON 바이트 해시는 양쪽 모두 `ec0ddaea6ae2adb052c0b21fb58175831e2c5dd1ebc9dae64b2692b664fe1088`였다. 비교·해시·입력 처리 전체 시간은 약 113.98초, 공통 JSON 파싱은 0.472초였다. 표의 정규화 시간은 입력 해제·JSON 파싱·비교 해시 시간을 제외하고 가벼운 FEN/PV 호출 카운터 비용을 포함한다.

입력 SHA-256 `feb08110ffcef588f05c30bb7ca93f5e19897e85c3d84678aff076f51dd84e2b`는 전후 그대로였다. 로컬 Zstandard 프레임 체크섬을 검증했고 네트워크 전송은 0바이트였다. [전체 원시 검증 JSON](../reports/quality-selected/validation.json)과 [요약 CSV](../reports/quality-selected/summary.csv)에 코드 해시, 소스 커서, 호출 수와 시각을 보존했다.

모든 후보가 잘못된 레코드는 거부 사유를 보존하기 위한 전체 fallback 때문에 오히려 비용이 늘 수 있다. 이 코퍼스에서 라벨 동등성이 확인됐다는 사실을 임의의 다른 데이터 소스 전체에 대한 보증으로 확대하지 않는다. 기본값 채택은 전체 학습 파이프라인의 이득과 학습/복구 검증을 함께 확인한 뒤 판단한다.
